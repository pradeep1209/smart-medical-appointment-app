# Physical phone usability session

Automated device checks do not replace observations from real participants. This protocol is ready for a small volunteer session after the final acceptance build is installed. Use fictional data only. Do not record names, medical histories, phone notifications, or unrelated apps.

## Procedure

Ask each participant to use CareSlot without coaching. Explain that it is an offline college demonstration with local personas rather than real accounts. Stop if the participant becomes uncomfortable. Record anonymous participant codes, task completion, elapsed time, errors, requests for help, and a short observation. Do not invent results for a session that has not happened.

## Tasks

1. Choose a fictional patient, find a doctor, and book a future visit. Read the confirmation summary before saving.
2. Locate that appointment, change its time, then cancel it.
3. Open a care plan and request a refill. Explain what Awaiting review means.
4. Switch to Clinic demo, locate a pending refill, and record a fictional review decision.
5. With larger text enabled, locate a visit and read its doctor, time, patient, and status. Restore the participant's original font setting afterward.

## Acceptance

All core tasks must remain possible without clipped actions, ambiguous success states, or accidental cancellation. Prioritize problems that cause an incorrect booking, missing records, or misunderstood refill status. Report the number of participants and the conditions. These observations measure usability of a student prototype, not medical effectiveness.
